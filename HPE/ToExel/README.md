# Экспорт аудита в Excel

Запуск из корня проекта: `python ToExel/main.py`. Выберите папку с собранными
JSON или ZIP. Результат — `Аудит_результаты.xlsx` в выбранной папке.

Основной лист **Аудит** содержит инвентаризацию и отдельные колонки прошивки,
State, Health, HealthRollup и DIMMStatus. В строке сервера
в колонке «Версия прошивки» указаны BIOS и iLO через точку с запятой.
Также указаны политика питания PowerRegulatorMode и
поведение после потери питания PowerAutoOn.

Температуры и отдельные строки датчиков в Excel не выводятся.

В итоговом файле только два листа: **Аудит** и **Группировка_PN**.
Группировка показывает количество компонентов по P/N для каждого сервера.
Повторный JSON того же сервера пропускается. Дополнительные диагностические
листы «Прошивки», «Статусы», «Температуры» и «Питание» не создаются.

В отчёт попадают только сведения из выгрузки: отсутствующие версии, показания
и статусы оставляются пустыми. Ноль и False сохраняются.
В колонках состояний нормальные значения (OK, Enabled, GoodInUse, Up,
LinkUp, Operational) выделяются зелёным. Ошибки и предупреждения
(Critical, Warning, Failed, Error, Degraded, MapOutError,
MapOutConfiguration, DegradedA3DC) выделяются красным.
Неизвестные состояния и отсутствие компонента остаются без подсветки.
Цвет применяется к ячейкам статуса, а не к совпадающим словам
в названиях компонентов или версиях прошивки.

## Проверка

Установите зависимости проекта и из его корня выполните:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют все семь файлов `ToExel/examples/server_info0.json` —
`server_info6.json`. Проверяют значения непосредственно по исходным JSON,
дубли ссылок, пустые данные, нули, критические состояния, версии прошивок,
запись и повторное чтение XLSX, повторный запуск экспорта,
сохранение цветов, пустые ячейки и наличие только двух итоговых листов.
