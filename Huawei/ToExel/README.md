# Huawei / xFusion Redfish → Excel в формате исходного Dell-аудита

В проекте **нет зависимости от `artifact_tool`**. Экспорт XLSX выполняется через **`openpyxl`**.

## Что воспроизводится из Excel-образца

Листы **точно в том же порядке**:

1. `Аудит` — 18 колонок (`A:R`); сервер отдельной строкой, затем физические компоненты, затем две пустые строки. Исправленная **фактическая заливка** в `I:L`: `Critical` — красная, `Warning` — жёлтая, `OK`/`Enabled` — зелёная, пустые значения без заливки. Та же логика для соответствующих столбцов листа `Health`.
2. `Группировка_PN` — для каждого сервера **отдельная строка S/N сервера** (столбец B, аналогично «Аудит»), затем заголовок P/N и количество компонентов; S/N записывается однократно перед компонентами. На этом листе нет заливок, границ, цветного шрифта или другого оформления ячеек; сохранена только ширина колонок для читаемости.
3. `Сводка_серверов` — показатели сверху, совместная группировка BIOS + iBMC, независимые группировки BIOS и iBMC.
4. `Микрокоды` — тип, модель / P/N, версия, количество компонентов и серверов, назначение прошивки.
5. `Health` — строки компонентов/серверов с явно проблемным состоянием; **S/N сервера указывается только в первой строке блока ошибок данного сервера** и не повторяется в остальных строках.

В архиве есть `layout_template.xlsx`: **шаблон оформления без данных Dell**. Он необходим для точного переноса стилей и ширин колонок. **Не удаляйте и не переименовывайте его**: он должен лежать рядом с `huawei_excel.py`.

Из-за различий Redfish Dell и Huawei поле `iDRAC` заменено на `iBMC`. Колонки питания `M:R`:

| Колонка | Имя | Источник JSON |
|---|---|---|
| M | `CustomPowerPolicy` | `Systems/1/Bios#/Attributes/CustomPowerPolicy` |
| N | `PowerSaving` | `Systems/1/Bios#/Attributes/PowerSaving` |
| O | `PowerConsumedWatts` | `Chassis/1/Power#/PowerControl/0/PowerConsumedWatts` (может быть иной индекс) |
| P | `Режим PSU` | `Chassis/1/Power#/PowerSupplies/*/Oem/Huawei|xFusion/ActiveStandby` |
| Q | `Power Capping` | `PowerControl/*/Oem/Huawei|xFusion/PowerMetricsExtended/PowerLimitActivated`; лимит `PowerLimit/LimitInWatts`, если задан |
| R | `ExpectedRedundancy` | `PowerControl/*/Oem/Huawei|xFusion/ExpectedRedundancy/@odata.id`; ссылка разрешается в `Sharing`/`Failover`, при невозможности — сохраняется как есть |

Столбцы «Резервирование» и `RedundancyEnabled` удалены. S/N сервера остаётся в колонке B на листе «Аудит».
**Важно:** на xFusion 1288H V6 поле `CustomPowerPolicy` отсутствует в предоставленных JSON. Оно остаётся пустым, не подменяется `PowerSaving`. `ActiveStandby` показывается отдельно для PSU1/PSU2, а не преобразуется автоматически в предполагаемый режим балансировки. `Sharing` и `Failover` — две записи Redfish Redundancy, значение `Health` у группы `Failover` в логах не указано; это явно отмечено вместо вывода «резервирование исправно». Поля, у которых нет подтверждённого эквивалента (`Spare P/N` и другие), не заполняются вымышленными значениями.

Аппаратные P/N, S/N, версии и состояния не выдумываются. В `Группировка_PN` для отсутствующих P/N используется **только текстовая метка группы** `UNKNOWN_PN::<категория>`, как в исходном отчёте Dell. В `Аудит` P/N остаётся пустым.

Сведения о происхождении компонентов (`Redfish` URL) помещены в `Комментарий`, а `Health` содержит отдельные столбцы с путём Redfish и исходным JSON. Версии резервных прошивок отражаются отдельно от текущих.

## Установка на Windows

В PowerShell из корня вашего репозитория:

```powershell
& .\.venv\Scripts\python.exe -m pip install -r .\Huawei\ToExel\requirements.txt
```

**Перенесите все файлы из архива в `Huawei\ToExel`, включая `getFromJSON` и `layout_template.xlsx`.**

## Запуск

Весь архив логов:

```powershell
& .\.venv\Scripts\python.exe .\Huawei\ToExel\main.py "C:\logs\server_logs_Huawei_AB.zip" --output "C:\logs\Аудит_Huawei.xlsx"
```

Папка с `redfish_full.json`:

```powershell
& .\.venv\Scripts\python.exe .\Huawei\ToExel\main.py "C:\logs\servers" --output "C:\logs\Аудит_Huawei.xlsx"
```

Без аргументов открывается окно выбора папки с JSON-файлами.

## Автотесты

```powershell
& .\.venv\Scripts\python.exe .\Huawei\ToExel\run_tests.py "C:\logs\server_logs_Huawei_AB.zip" "C:\logs\Аудит_Huawei.xlsx"
```

Они проверяют:
- структуру и число листов, число блоков серверов, заголовки и контрольное оформление;
- `Critical` / `Warning` и `HealthRollup` (включая K) на реальных и синтетически изменённых состояниях;
- все шесть полей питания (`M:R`) с проверкой исходных JSON-путей; отсутствие удалённых столбцов;
- сопоставление P/N, S/N и прошивки **в каждой строке компонента** с оригинальным полем Redfish JSON (по сохранённому источнику);
- группировку по серверам и количествам с ровно одним S/N на блок, отсутствие оформления на `Группировка_PN`, а также S/N однократно на сервер в Health;
- независимые сводки и результаты `Health`;
- соответствие прошивок FirmwareInventory и их назначения;
- неизменность модульного интерфейса папки `getFromJSON`;
- безопасное экранирование строк, начинающихся на `=`;
- отсутствие импортов `artifact_tool` и корректность ZIP/XLSX.

## Файлы

- `main.py` — CLI и разбор ZIP/папок JSON;
- `huawei_parser.py` — нормализованный парсер Huawei V5 / xFusion V6;
- `huawei_excel.py` — форматирование и экспорт по образцу Dell на `openpyxl`;
- `layout_template.xlsx` — стили и геометрия исходного Excel, **без данных**;
- `getFromJSON/` — все модули API первоначального проекта;
- `tests/` и `run_tests.py` — тестирование на реальных логах;
- `requirements.txt` — зависимости.
